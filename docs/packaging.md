# Packaging and tests

The ways to get tg into a project, plus the test suite that checks every build.

## Ways to use tg

| | How | Good for |
|---|---|---|
| FetchContent / `add_subdirectory` | see [Getting started](getting-started.md#use-tg-in-your-own-project) | most projects: always builds with your flags |
| Installed package | `cmake --install` then `find_package( tg )` | system-wide installs, prebuilt SDKs |
| vcpkg | overlay port in `packaging/vcpkg/ports/tg` | projects already on vcpkg |
| Conan 2 | recipe in `packaging/conan` | projects already on Conan |
| Single header | `tg_single.h`, generated by `tools/amalgamate.py` | dropping into a project with no build system changes |
| Zip / tgz | `cpack` | handing out headers + static libs |

### Install + `find_package`

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
cmake --install build --prefix /opt/tg
```

```cmake
find_package( tg 0.5 CONFIG REQUIRED )                    # CMAKE_PREFIX_PATH=/opt/tg
target_link_libraries( myapp PRIVATE tg::app )            # or tg::tg + tg::soft / tg::win32 + tg::d3d11 / tg::d3d9
```

The install contains:
- `include/tg/...`, with the backend headers in `include/tg/backends`. The targets add that folder to the include path, so `#include "soft_renderer.h"` works as it does in the source tree.
- The static libraries.
- `lib/cmake/tg`, holding the config, targets and version files.
- The third-party license notices in `share/tg/third-party`.

`tgConfig.cmake` finds tg's dependencies itself: Threads always, plus FreeType, HarfBuzz or GLFW when the build used them. Those dependencies should come from the system, vcpkg or Conan. If CMake downloaded FreeType or HarfBuzz in-tree, the install warns you, because the package will need them installed too. A downloaded GLFW is installed next to tg.

`tg::webview` isn't part of the install: its WebView2 / WebKitGTK setup is build-tree only. Use it through FetchContent or `add_subdirectory`.

### vcpkg

```sh
vcpkg install tg --overlay-ports=<tg>/packaging/vcpkg/ports
vcpkg install "tg[freetype,harfbuzz]" --overlay-ports=...
```

- Features: `app` (default; pulls `glfw3` on non-Windows), `freetype`, `harfbuzz`.
- The port downloads tag `v<version>` from GitHub. Fill in `SHA512` for a release; vcpkg prints the right value on the first try.
- To build from a local checkout, set `TG_SOURCE_DIR` and add it to `VCPKG_KEEP_ENV_VARS`.

### Conan 2

```sh
conan create packaging/conan --build=missing
conan create packaging/conan -o "tg/*:freetype=True" -o "tg/*:harfbuzz=True" --build=missing
```

- Options: `app` (default on; requires `glfw/3.4` off Windows), `freetype`, `harfbuzz`.
- Consumers use `find_package( tg )` and the same `tg::tg`, `tg::soft`, `tg::app` and `tg::win32 / d3d11 / d3d9` targets.
- `packaging/conan/test_package` renders a label with the software renderer.

### Single header

```sh
python3 tools/amalgamate.py -o tg_single.h          # or: cmake --build build --target tg_amalgamate
```

```cpp
// in exactly one .cpp:
#define TG_IMPLEMENTATION
// in every file that includes it, the backends you want:
#define TG_BACKEND_SOFT          // software renderer
#define TG_BACKEND_GLFW_GL3      // GLFW + OpenGL 3        (link glfw, GL)
#define TG_BACKEND_WIN32         // Win32 + D3D11 + D3D9   (link d3d11 d3d9 d3dcompiler dxgi imm32 ole32 shell32 uuid)
#define TG_APP                   // tg::App on top of the chosen backend
#include "tg_single.h"
```

- The header is about 3.4 MB, most of it the embedded fonts. It holds the core, the backends and the bundled stb and nanosvg.
- One translation unit that big needs `/bigobj` on MSVC and `-Wa,-mbig-obj` on MinGW.
- Linux also needs `-lpthread -lutil`, for the terminal's pty.
- The optional FreeType, HarfBuzz and WebView parts aren't in it.
- CTest builds the golden-image test from the single header too (`golden_single_header`), so it's checked against the same pixels as the normal build.

### Zip / tgz

```sh
cd build && cpack                # tg-0.5.0-<system>-<arch>.zip / .tar.gz
```

This is the same tree as `cmake --install`.

## Tests

`ctest --test-dir build` runs:

| Test | What it checks |
|---|---|
| `headless` | Every page of the demo driven by scripted input: clicks, drags, typing, binds, undo, docking, file drops, IME, and so on. There are hundreds of `CHECK`s. See [Testing](testing.md). |
| `golden` | Small scenes (controls, text, charts, table, docking, gradients, light theme) rendered in software and compared with `tests/golden/ref/*.png`. |
| `golden_single_header` | The same scenes, built from `tg_single.h`. |

Golden images:
- A pixel counts as different when any channel is more than 40 off. A scene fails when more than 0.4% of its pixels differ.
- On failure the test writes `<scene>.actual.png` and `<scene>.diff.png` into the build directory. The diff shows differences in red.
- After an intended visual change, run `cmake --build build --target tg_golden_update` and commit the new references.
- The references come from the default stb_truetype rasterizer. FreeType builds rasterize differently, so they skip the golden tests.
- The current references match pixel for pixel on GCC, Clang and MinGW (under Wine).

## CI

`.github/workflows/ci.yml` builds and tests on several platforms, then packages:

| Job | Configurations |
|---|---|
| Linux | GCC, Clang, and GCC + FreeType + HarfBuzz |
| Windows | MSVC, with `tg::App` on Win32 and on GLFW |
| macOS | GLFW + GL3 |
| Package | `cpack` zips and `tg_single.h`, uploaded as artifacts |

When a golden test fails, CI uploads the diff images.
